# DEV_AUX95: prospective paid-node clock control

The question is whether a single TRAIN-derived cost clock improves finite actual
W-L utility per paid search node relative to the existing fixed-eta mean batch.
It does not claim that update frequency caused the preceding depth result.

Both arms use pure material full-width D3 Alpha-Beta, no qsearch/TT/SEE/material
ordering/prover. Search targets/one-sided losses/mean batch/free6 features are
identical. Weights remain frozen inside a query and the pre-update chosen action
is executed. The fixed uniform training foe stays D2. All four exposed generated
rules and all four random initializations are retained, with no human-price fit.
Each arm receives200000 candidate+foe+failed search nodes; prefix moves are actual
legal uniform moves. Rules, model recipe, H128, query budgets, slot order and two
fixed evaluation opponents were frozen before any new TRAIN query.

Fixed arm: eta=.05 at each complete candidate observation.
CostClock arm: eta=.05*(N_current-N_previous)*27795/3200000.
The reference comes ONLY from old D2 Tree TRAIN:3.2M all-paid nodes and27795
complete candidate observations, independently recounted before this experiment.
The boundary resets at EVERY complete candidate observation, including zero
loss/zero-gradient cases, and persists across games within one arm. It starts
at0 per arm. Opponent and incomplete-search nodes accumulate as cost. A failed
query admits no partial targets and does not move the boundary. Trailing cost
is charged but receives no invented terminal/UNKNOWN update. No rate clipping,
coefficient normalization, model/seed selection or DEV rate fitting is used.

The clock's accumulated eta telescopes to.05*27795/3200000 times covered paid
nodes. That identity is an accounting control, not a convergence guarantee.
Increasing effective steps may increase instability or saturation; all such
outcomes are retained. The new scheme changes visited states, targets, runtime
and query costs, so a positive result cannot isolate frequency as a pure cause.
This is a mean batch variant, not a literal summed historical TreeStrap.

Evaluation is a separate NEW384-slot paired panel:4rules*4initials*2families*
2roles*2fixed price opponents*3treatments(initial,Mean,CostClock), candidateD3
versus fixedD2foe. Primary contrast CostClock-Mean; both versus initial retained.
Actual complete-rule public Session terminals alone determine W/L/D. H128 and
resource UNKNOWN/missing contribute[-1,1], never draws or quantity rewards.
Rules are TRAIN-exposed; fresh PRNG family IDs do not guarantee unseen states.
Root overlap/initial terminals are explicitly recounted without filtering.
Crossed rule/seed/family resampling is descriptive in this small correlated
panel, not guaranteed confidence, equivalence or a population-winner test.

One serial producer, TRAIN cap2400s then EVAL cap900s, no old cap continuation,
no added worker/fee. Total expected duration<120min; all candidate/foe/baseline/
failed work, wall time and engineering limitations reported separately. Full
history/clock/gradient replay, all model/slot binding, prospectively first
complete query per arm unpruned, all-seed curves and actual sealed fresh replay
are correctness evidence with explicit same-Core scope, not all-domain proof.

Interpretation boundary decided before any EVAL: CostClock changes both the
average step magnitude and its allocation across queries. Even if it improves
W-L, this two-arm study cannot establish that dynamic cost-dependent allocation
beats a larger FIXED eta. A future third-arm test must freeze its multiplier
from TRAIN-only counts before future validation, retain all seeds and count all
cost; no retrospective fitting to this panel. Conversely, decreasing the local
fixed-target loss does not guarantee improved playing strength or calibration.
The interior-bound audit reruns only the prospectively first candidate query
per arm, intercepts Sample construction in a separate audit process, matches
actual receipts/actions/nodes, and independently solves each exact-history
interior subtree. Its separate paid work is not training or fitness.

Additional descent/geometry/diversity diagnostics were designed during TRAIN,
before any EVAL; they are descriptive, not all pre-TRAIN hypotheses. They never
change a learner, rate, admitted root, selected model or validation slot. Runtime
retains complete available Session semantics; four exposed4x4 rules do not prove
coverage of every generated aux/trigger/declaration combination.
