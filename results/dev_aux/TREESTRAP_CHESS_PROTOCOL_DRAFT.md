# Standard-Chess TreeStrap comparison — protocol draft only

Status: not registered, not launched; no new seeds, roots, or outcomes selected.

## Decision question

Under equal total search-node cost, does the existing one-sided TreeStrap update improve actual standard-Chess terminal W/L versus the episode TDLeaf(.95) baseline and the same initialization? Does its denser search-node signal translate to lower training loss without sacrificing held-out strength? Retain the previous finite-WDL proposal-selection arm (one seeded-coordinate multiplicative proposal per seed) as a predeclared cost-matched control if the complete comparison remains below the two-hour assessment threshold.

## Candidate protocol to freeze before any outcomes

- Reuse the five-feature linear material model from the checked Chess path: pawn fixed at 1; remaining coefficients initialized from the same preregistered random distribution for paired method arms. No human price priors, material-based move ordering, SEE, pruning priors, NNUE or positional features.
- Compare `TreeStrap` interval loss over complete search receipts' internal alpha-beta `Sample(lower, upper)` records against `TDLeafEpisode(lambda=.95)` using the root PV/search target. Reuse one identical search implementation/receipt source for both methods; do not compare task2492's separate AlphaBeta implementation against task2594's TrainingSearch and attribute the difference to learning alone. Bounds remain one-sided; incomplete/resource-cut searches are not exact values and their unknown outcomes remain censored.
  The task2492 `run.py` cannot be reused unchanged as the experiment runner: it always searches with the learner model on both sides, so it is self-play. Build a small shared-receipt runner that selects the candidate model only for its assigned color and the same frozen foe model otherwise; charge both sides' nodes to the arm budget. Unit-test actor/model routing and verify both learners receive the same complete/incomplete receipt contract.
- Use the same coefficient-independent depth/search configuration and randomized opening roots for both methods. Pair by seed and training-start history; count every candidate and fixed-opponent search node toward the same per-arm total. Keep opponent, side/color, and opening distribution fixed across methods. Compare the complete learner packages: TDLeaf also receives actual terminal return while TreeStrap currently trains from internal search bounds. Do not call this an isolated causal estimate of the marginal value of internal targets; add a preregistered hybrid arm only if that mechanism is the decision question.
- Evaluate initialization and both learned endpoints on preselected full-history Chess roots disjoint from every training start and from prior task2594 evaluation starts. Use the same fixed opponent, color balance, search limits, and total evaluation nodes for each endpoint. Only actual rule-terminal W/L/D counts as strength; UNKNOWN stays censored with conservative paired bounds.
- Freeze the WDL one-coordinate proposal-selection rule, number of proposal tries, acceptance rule, and compute accounting before exposure; do not describe this as a broad grid over all prices. Report all training/evaluation node and wall-clock totals, losses, finite paired W/L bounds, per-seed results, failures and partial/censored slots. Do not select checkpoint, seed, grid width or root from evaluation outcomes.

## Cost evidence and open registration fields

Task2594's four-seed, 4M-node Chess candidate training took 513.875 s; its 768-slot evaluation took 1,711.096 s. The task2492 source archive SHA matches its manifest and all four extracted run/learner/adapter/test sources match `started.json`; its original TreeStrap smoke ran 720k registered node budget across six arms in 85.010 s. These are separate historical runs, not a reliable estimate for the proposed complete protocol: TreeStrap has more update work and the WDL control adds cost. The bounded task2612 scan used the common TreeStrap/TDLeaf receipt path: 8 paired arms, 100k candidate-plus-foe nodes each, 111.982s total. It did not include the WDL proposal arm or held-out evaluation and its small update-time difference is order-confounded. Before registration, pin a shared-receipt evaluation cost scan and source hashes for all training/evaluation/control arms, estimate end-to-end wall time including setup/audit, and freeze caps. See results/dev_aux/task2612/REPORT.md. If expected to reach 120 min, send Dot the necessity assessment first; otherwise proceed under the established threshold without extending any old cap.

## Completion bar and limits

A finite actual-W/L comparison with independent full-history starts and complete node/wall-time accounting is the decision result. Lower TreeStrap loss or more internal targets alone is not success. Four (or other preregistered) seeds remain a finite pilot, not a population guarantee or faithful paper reproduction. Do not transfer the conclusion to Generic rules until this standard-Chess comparison is audited; then carry the same learner and protocol to complete Generic rules as a separate registered stage.
