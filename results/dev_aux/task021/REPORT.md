# Task021: pinned source shape and applicability argument
This audit concerns the original effect-loop shape and frozen per-pattern prototype, not a general compiler proof. Source assertions and hashes are recorded separately in static_applicability.json after execution.
For the current source, a board/hand/type effect executes the original checkpoint then the original dynamic helper operands in declaration order. Pruning a comparison whose left side is the constant bound effect kind removes only the unreachable literal branch. Occupancy, owner/type checks, square/type resolution, working-position events and original errors stay in the helper.
An auxiliary effect executes the same checkpoint, appends its exact frozen record and advances to the next effect. It still applies after dynamic promotion and transition triggers, in the original deferred auxiliary loop; expiry and side switch remain outside the replaced loop. Task019 executes a composed board/type/bool case, not merely preparation. Task020 witnesses carrier/pattern fallback authority.
The inspected original loop has no for-else, break, nested function or yielded control. Its auxiliary continue is immediately after append and is the only skipped helper path. The helper assigns kind once from effect.kind, uses literal Eq/In conditions and does not shadow/reassign kind. CompiledEffect and CompiledMovePattern are frozen records; effects is a tuple. The captured source AST is compared with own baseline and read-only primary source; physical hashes retain line-ending differences.
Applicability limits remain explicit. The transform does not dynamically admit future changed source shapes. Frozen IR records do not imply every nested Mapping is immutable; kind/effect order are the invariants needed here, and unsafe mutation is outside this preparation contract. Dynamic module helper replacement is not equivalent to captured generated code; primary reported an actual live _apply_effect hook bypass, which is accepted as a real limitation rather than independently rerun. Removing Python iteration/branch work changes allocation surfaces, so callback parity does not establish arbitrary MemoryError equivalence. One module-global preparation is not a measured multi-game reuse design or concurrency guarantee.
Decision: retain this finite source argument with Task019/020 evidence; do not relabel it universal compilation acceptance. A later shared-template premise must bind actual pattern operands and independently re-establish these applicability conditions. No product, UI, defaults or backend changes.
