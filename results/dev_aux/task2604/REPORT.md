# Task2604 — task2492 TD learner entrypoint map

Question: Which of the existing task2492 producer entrypoints actually selects the episode-frozen TDLeaf variant, and what adapter boundary exists for migrating the learner to complete Generic rules?

Method: static AST/source inspection of only task2492/run.py, learning.py, episode.py and adapters.py. Hashes and symbol map are emitted by audit_task2492_td_entrypoints.py. No saved result, game record, query trace or weight vector was opened; no producer or training code was executed.

Acceptance: the map identifies the learner classes implemented, the classes imported by the historical producer, the actual training call sequence, and the adapter's explicit qsearch limitation. It must not describe historical training as episode-frozen unless the producer imports that class.

Finding: task2492/run.py imports Model, AlphaBeta, TreeStrap and TDLeaf from learning.py. It does not import or instantiate TDLeafEpisode from episode.py. The producer calls learner.observe(model, receipt) after each search and learner.finish(model, outcome) at episode end. In learning.py, TDLeaf.observe applies the update at each call; episode.py's TDLeafEpisode instead accumulates rows with frozen episode weights and applies one backward eligibility-trace update in finish. Thus the episode-frozen implementation exists as a reusable component, but this producer's TD route is the online variant. Any prospective reproduction must name and wire its intended variant explicitly; this source audit makes no claim about which exact byte snapshot produced historical outputs.

Migration boundary: ChessEnv uses python-chess as legal/terminal authority and supplies five material-count features, action push/pop, check and capture/promotion tactical tests. SessionEnv adapts complete GameSession choices/history and task2397 material channels, but explicitly permits qdepth=0 only; it has no Generic tactical predicate and rejects qsearch admission. README also directs future Generic scoring through task2511 ScoringSessionEnv to preserve non-scoring terminal states rather than assigning them numeric labels. A standard-Chess TD proof-of-path therefore does not by itself establish full-Generic qsearch or terminal-label compatibility.

Decision: treat the learner and producer wiring as separate audited components. Before a future controlled comparison, freeze which TD implementation is intended, bind its source hash to the producer and tests, and retain actual terminal W/L/D as the strength endpoint. No training/result conclusion or change to product defaults follows from this map.
