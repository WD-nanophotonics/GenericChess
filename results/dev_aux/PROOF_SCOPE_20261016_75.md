# Finite positive-certificate lifting — segment75

This is a scoped soundness argument and executable feasibility evidence. It is
not an unconditional quotient of the complete Session state space. UNKNOWN,
cycles, failed admission and failed verification remain UNKNOWN. A graph search
result is only CANDIDATE_WIN_GRAPH until independently verified. No production
player, existing fixed learner, product default or PRIMARY backend adopts it.

## What is retained

The actual root must replay through its public GameRecord and match complete
state/result. Ended Sessions are rejected before canonical construction. The
certificate binds the exact root record/state, rule fingerprint and target.
Full typed Position includes owner, base/current identity, promotion, hands,
side, aux state and explicit shape. Field equality also checks exact types.
Repetition identity is a separate authority; it must be injective over all
reachable certificate nodes. No board-current-type projection replaces either.

At a target node the witness supplies one public legal choice; at a defender
node it supplies every public legal choice. Every edge strictly lowers a fixed
nonnegative integer rank. Rank-zero leaves are actual target-winner rule results.
The actual root rank fits remaining rule plies. Each future identity has fewer
than repetition_limit-1 occurrences in the actual past. The current root identity
cannot recur along a strictly decreasing-rank path.

Consequently no certificate path repeats an identity, and adding its one future
occurrence cannot reach the repetition threshold. Every path reaches a genuine
winner leaf within the remaining plies. Other history-bearing adjudications and
out-of-band declarations are explicitly refused. Branch sharing alone is not a
path repeat. This establishes finite positive-strategy lifting under these
conditions, not DRAW/LOSS equivalence or unrestricted transposition reuse.

Terminal priority is preserved: mate/stalemate precedes ordinary repetition and
max-ply in these public executors. A terminal future node is therefore not a valid
counterexample to repetition priority. The guard may conservatively reject some
wins; it must never manufacture a draw or accept a false positive.

## Canonical construction and semantic authority

A semantic GameSession built from board rows starts side0, empty hands and empty
explicit aux state. Reusing that constructor would lose actual Position fields.
The old2179 graph refused semantic executors; no old semantic falseWIN is claimed.

The2191 prototype constructs an explicit fresh-history immutable Core GameState
from the complete Position, derives its real repetition key, and recomputes
terminal_result through public Core. It uses public legal_actions/apply_action.
It never writes GameSession internals, recompiles a ruleset to manufacture an
outcome, or reads movement metadata from _legacy_compiled. Both actual compiled
semantic classes use IR/support for limits. The real root and actual execution
cursor remain full GameSessions. The2197 baseline control gives62 exactly equal
node-bounded old/new query pairs, including witnesses; not a timing speedup.

2191 conservatively refuses S4 and transition triggers. Separate2199 scope admits
them after checking the actual dependency: semantic_executor._violates_postconditions
consumes parent/child Position plus action; _exists_s3_reply explicitly excludes
terminal/repetition/max-ply/history. S4 is a forbidden conjunction, not a bonus or
an invented mate label. Trigger/lifetime effects transform complete Position/aux.
The actual engine remains action/terminal authority in every edge. This dependency
review and the tested examples do not prove complete generated-domain coverage.

Actual S4 controls in2200 use one inventory-preserving rule fingerprint: a mating
capture is forbidden, whereas a quiet mating move is legal. A separately compiled
no-S4 control supplies an actual lookalike capture, which the real S4 submit and
independent verifier reject. Actual castling and king-leave triggers preserve45
full legal successor fronts/records.2201 also checks a genuine proved mate whose
rook move clears its trigger right, and unrolls to the original full-history tree
verifier. Unsupported automatic/no-progress/consecutive/repeated-cycle policies,
non-draw perpetual handling and declarations remain refused in both prototypes.
