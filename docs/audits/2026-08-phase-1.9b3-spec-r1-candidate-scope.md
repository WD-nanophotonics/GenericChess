# Phase 1.9B-3 Specification R1 — Candidate-Scoped S4 Assertions

Status: frozen specification correction.

Baseline specification:

`47ae39b5f858701006cc5ba316963220b263a1af`

## Finding

ADR-016 freezes S4 postconditions as predicates over one concrete candidate
after that candidate's S3 trial transition. For
`[opponent_checked, no_legal_reply]`, rejection is the conjunction:

`opponent_checked(child) AND NOT EXISTS_LEGAL_REPLY_S3(child)`.

Therefore `opponent_checked == False` leaves that candidate legal and the
reply probe is not run.

The original SPEC-01, SPEC-03 and SPEC-07 assertions accidentally filtered
only by `pattern_id`. Their fixtures intentionally admit multiple concrete
candidates for the same pattern, including candidates whose
`opponent_checked` value is false. Those assertions therefore demanded
pattern-wide rejection and contradicted ADR-016's candidate-level truth
table.

## R1 correction

No semantic contract changes.

No ADR-016 truth-table changes.

No fixture geometry, drop-mask, postcondition, IR, schema or production
changes.

The frozen tests are corrected to identify concrete candidates:

- SPEC-01: drop to `(7, 5)` is the caged checking/no-reply candidate and must
  be absent; drop to `(0, 1)` is a non-checking control and must remain legal.
- SPEC-02: the same drop to `(7, 5)` must remain legal when the cage is
  removed and the reply side has an S3 reply.
- SPEC-03: the same move to `(2, 1)` is examined in both perspective
  positions; it is rejected when the reply-side anchor is checked and
  retained when only the mover-side anchor is checked.
- SPEC-07: public `legal_actions` and `legal_successors` exclude only the
  forbidden `(7, 5)` semantic drop while retaining the `(0, 1)` control;
  forged `apply_action` for `(7, 5)` remains `IllegalActionError`.

## Frozen conclusion

S4 legality is candidate-scoped, never pattern-scoped. An implementation
must not satisfy these tests by globally removing every action sharing a
`pattern_id`.
