# Phase 1.9B-2 Pre-Executor Audit

Baseline: `6d6ddd4f00d059e6647a37664044a7030a4f802d` (`Harden semantic IR to executable completeness`).

This audit is specification material for the first Python semantic executor. It records source-confirmed facts that must be resolved before or during Phase 1.9B-2. It does not authorize Native/Search/Learner changes.

## Confirmed source facts

1. `CompiledSemanticIR` v2 now carries exact geometry IDs, normalized patterns, zones, aux slots and transition triggers. `validate_executable_completeness` checks that pattern-local runtime operands are typed and self-resolving.
2. `CompiledRuleSet` still owns generic execution support data not present in `CompiledSemanticIR`: board size, stripped/full type metadata, initial position, drop masks, promotion masks, empty-mobility data, repetition/max-ply/stalemate configuration.
3. `lower_legacy_to_ir()` currently skips `PieceType.is_anchor` types while legacy Core move generation does not skip anchors. Therefore semantic normalization currently does not preserve normal anchor movement.
4. Legacy IR patterns use `promotion_mode="inherit_compiled_masks"`, but those masks are not stored in `CompiledSemanticIR`.
5. `own_anchor_safe` requires knowing which current types are anchors. Current legacy attack helpers obtain that from `CompiledRuleSet.types_by_id`; `CompiledSemanticIR` has no equivalent type metadata.
6. Existing `position_key()` hashes board/hands/side/ruleset only. It has no auxiliary semantic state because `Position` has none yet.
7. Existing terminal code depends on legacy `has_legal_action`, legacy attack semantics and `CompiledRuleSet` repetition/max-ply/stalemate settings.
8. `_explicit_geometry_path()` rotates explicit offsets/directions for owner 1 unconditionally, although `RuleGeometrySpec.owner_relative` is an explicit field. `owner_relative=False` is therefore not yet implemented as specified.
9. Current attack semantics intentionally differ from legal capture semantics: pseudo-attacks include the first occupied ray square and protected friendly squares; anchors are attackable but never capturable. The semantic executor must preserve this distinction.

## Blocking contract questions resolved by this specification

### A. Executor input

The executor MUST NOT use `_legacy_compiled` as a hidden semantic oracle. Phase 1.9B-2 shall introduce a typed, immutable generic support payload owned by `CompiledSemanticRuleset` (name may be `CompiledSemanticSupport` or an equivalently explicit name). It must contain every non-pattern datum required by Core execution while excluding movement atoms as semantic instructions.

Required support categories:
- `board_size`;
- initial position data;
- stripped type metadata sufficient for anchor detection, promotion target validation and piece construction;
- drop masks;
- promotion allowed/forced masks and any precomputed target viability information required to exactly preserve legacy promotion behavior;
- repetition limit, max ply and stalemate result.

The semantic executor may consume `CompiledSemanticRuleset.ir`, this support payload, the current `Position`, and a candidate/action binding. It may not consult high-level `RuleSet`, `RuleSemanticAction`, `PieceType.movement_atoms`, debug names, or `_legacy_compiled`.

### B. Anchor movement

All movable types, including anchors, must be present in the normalized executable pattern set. Anchor capture remains forbidden by legality, but anchor movement itself must not disappear during lowering.

### C. Coordinate ownership

`owner_relative=True` means the repository's existing 180-degree owner-frame transform: owner 0 uses `(df,dr)`, owner 1 uses `(-df,-dr)`. `owner_relative=False` means absolute coordinates/offsets and MUST NOT rotate for owner 1.

The same rule applies consistently to explicit geometry and offset/fixed square references. A fixed square reference with `owner_relative=True` is owner-frame relative and rotates by board symmetry; a fixed square with `owner_relative=False` is absolute.

### D. Aux state and identity

Auxiliary legality-affecting state belongs to `Position`. It must participate in position identity/repetition keys whenever differing values can change future legal actions. Legacy positions with no semantic aux slots retain a canonical empty aux state and legacy keys must remain stable.

### E. Trigger/effect resolution order

For one semantic action transition:
1. Resolve/bind all action operands from the pre-action position and pre-action aux state.
2. Copy parent aux state to the child working state.
3. Expire parent values whose lifetime is `expire_next_turn` to their defaults.
4. Apply board/hand/type effects in declared order.
5. Detect transition-trigger events against the pre-bound action/board delta and clear the targeted aux slots.
6. Apply explicit aux-setting effects in declared effect order where required by the compiled effect sequence. A slot explicitly set by the current action after expiration survives into the child.
7. Switch side to move.

Implementation may organize helpers differently, but observable semantics must match this ordering and the existing frozen `EXPIRE_NEXT_TURN` contract.

### F. S0-S3 only

Phase 1.9B-2 implements geometry, target/path predicates, state/slot guards, pseudo-attack, trial transition, invariants, bounded effects, aux lifecycle and transition triggers. S4 `no_legal_reply` remains fail-closed and is deferred to Phase 1.9B-3.

## Acceptance principle

A passing implementation must make the specification tests executable without weakening them. If this contract conflicts with a source invariant not captured here, report `SPECIFICATION_BLOCKER` rather than inventing a local exception.
