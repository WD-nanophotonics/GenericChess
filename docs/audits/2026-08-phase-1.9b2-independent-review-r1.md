# Phase 1.9B-2 Independent Review R1

Reviewed implementation:

- spec: `cde9c1096e22b003260af92a9459bd01b6f5c53f`
- impl: `6a7bd95`
- baseline before spec: `6d6ddd4f00d059e6647a37664044a7030a4f802d`

Verdict of this independent review:

`REFERENCE_EXECUTOR_REQUIRES_REVISION`

The implementation branch preserved all frozen R0 specification files, which is
a successful use of the new spec/impl workflow. However, source review found
several correctness and architecture defects not covered by the R0 tests.

## Confirmed blockers

### R1-01 — PER_OWNER auxiliary state is not owner-separated

`CompiledAuxSlot.scope` supports `global|per_owner`, but runtime `Position.aux_state`
is currently keyed only by `slot_id`. Slot guards, aux effects, expiration and
semantic position hashing also resolve only by `slot_id`.

Observable consequence: clearing player 0's castling right can clear player 1's
right as well.

Required semantic contract:
- GLOBAL slot: one logical value.
- PER_OWNER slot: two logically independent values, one for owner 0 and one for
  owner 1.
- implementation representation is not prescribed, but identity, guards,
  effects, triggers and lifetime processing must all respect scope.

### R1-02 — transition triggers use final emptiness instead of transition events

Current `piece_leaves_square` and `piece_removed_from_square` both effectively
test `pre != None and post == None`.

This is incorrect for a capture:
- victim existed on watched square in the parent;
- `remove` removes it;
- a later `move` places the attacker on the same square;
- final square is occupied, so current code loses the removal event.

It also collapses `piece_leaves_square` and `piece_removed_from_square` into the
same observable condition.

Required contract:
- triggers are matched against a pre-bound transition event trace, not merely
  final occupancy;
- `move/shift` emits a `piece_leaves_square` event for its source piece;
- `remove` emits `piece_removed_from_square` for the removed piece;
- a later effect occupying the same square does not erase the earlier event;
- for a PER_OWNER slot, owner-relative trigger refs are resolved in the slot
  owner's frame, not simply the action mover's frame.

### R1-03 — ACTION_BASE/ACTION_CURRENT state-query binding is wrong

The current state-guard scan resolves `action_base` / `action_current` using the
piece currently being *scanned* by the query.

That makes a guard such as nifu:

`count(self, action_base, compare_field=base, same_file(TARGET)) == 0`

effectively match unrelated self pieces too, because each scanned piece is
compared with its own base type.

Required contract:
- action-relative TypeRef is bound once from the runtime action context;
- board move: actor is the piece at SOURCE in the pre-action position;
- drop: actor/base type is the exact drop type represented by the runtime action
  binding / normalized pattern;
- query candidates are compared against that pre-bound action type.

### R1-04 — enemy anchors are currently legally capturable

Semantic pseudo-attack correctly needs to include enemy anchor squares, but
legal generation must never emit an action that captures an anchor.

Current target filtering accepts any enemy piece and `remove` can remove the
anchor.

Required contract:
- pseudo-attack: anchor square may be attacked;
- legal action: any effect plan that captures/removes the opponent anchor as the
  action capture target is rejected.

### R1-05 — S4 is silently partially executed instead of fail-closed

`SemanticEngine` currently filters postcondition-bearing patterns out of its
S0-S3 pattern list but still constructs for an S4 ruleset.

That is partial/silent execution, not fail-closed behavior. A forged action can
also call the transition path with an S4 pattern id.

Required contract:
- an IR whose capability says `new_ir_core_executable=False` MUST be rejected by
  the B-2 runtime surface before gameplay;
- S4 rulesets must produce an explicit unsupported/fail-closed error;
- no partial action set may be exposed.

### R1-06 — semantic action application is forgeable

`SemanticEngine.apply(position, action)` currently transitions the supplied
binding directly. It does not establish that the action belongs to
`legal_actions(position)`.

A caller can provide a valid pattern id with an arbitrary source/target not
generated by its geometry/guards and reach transition code.

This violates the long-standing Core rule that public transition validates
legality before mutation.

Required contract:
- public semantic application validates ruleset identity, nonterminal state and
  legal-action membership before applying;
- any unchecked transition helper must remain private;
- a forged pattern/source/target/promotion binding raises the Core's normal
  illegal-action error family.

### R1-07 — B-2 has not been integrated through the public Core path

The frozen task required terminal/repetition integration through the public Core
path without creating a second parallel game engine.

Current legacy `core.transition.initial_state/apply_action`, `movegen.legal_actions`
and `terminal.terminal_result` remain legacy-only, while `SemanticEngine`
provides a separate public `legal_actions/apply/terminal_result` surface.

Required contract:
- existing public Core entry points must dispatch additively for
  `CompiledRuleSet` and `CompiledSemanticRuleset`, preserving legacy behavior;
- `SemanticEngine` may remain an internal/reference helper, but must not become a
  second public source of game-state transition truth;
- semantic `GameState` transition updates ply, semantic repetition key/counts
  and terminal status from the same public child-construction path.

### R1-08 — required legacy differential coverage is incomplete

The R0 task explicitly required comparison of:
- legal actions;
- transitions;
- terminal outcomes;
- historical position keys.

The implementation test compares legal-action *sets* on a small corpus and
separately checks key stability. It does not differential-test child
transitions or terminal outcomes.

Additionally, converting actions to a set can hide duplicate action generation.

Required:
- compare canonical legal actions without hiding duplicate-generation defects;
- for matched actions compare child board/hands/side/promotion state;
- compare terminal results over a deterministic reachable corpus;
- keep historical legacy `position_key` byte-stable.

### R1-09 — forced-promotion edge case diverges from legacy

Legacy `_promotion_variants` returns **zero variants** when promotion is forced
but every promotion target is structurally dead.

Current semantic `_promotion_choices` returns `(None,)` when `alive` is empty,
re-introducing an unpromoted action that legacy Core forbids.

Required: exact legacy behavior; forced + no alive promotion targets means no
legal action variant.

### R1-10 — multi-type semantic patterns are not binding-closed

A semantic action may contain multiple `type_ids`. For `legacy_atoms`, compiler
currently accumulates geometry ids across all selected types into one pattern.
Runtime then loops each type across all pattern geometry ids, producing a
type × geometry cross-product.

Drops have a related problem: runtime action identity has no explicit drop type
and transition currently falls back to `pattern.type_ids[0]`.

Required contract:
- every runtime action has an exact actor/drop type binding;
- a type may use only geometry compiled for that type unless the geometry is
  explicitly shared;
- compiler may split normalized patterns per type, or runtime binding may carry
  a type/geometry binding; either is acceptable if deterministic and explicit;
- executor must never choose `type_ids[0]` as an implicit semantic guess.

## Additional S0-S3 completeness issues

### R1-11 — hand state predicates are silently treated as false

The IR supports `location="hand"`, but current guard evaluation iterates board
pieces and skips candidates when location is hand.

Until hand-query semantics are implemented, a ruleset using a hand predicate
must be rejected/fail-closed. Silent false evaluation is forbidden.

This review does not prescribe a new hand-spatial DSL in R1.

### R1-12 — PATH_BETWEEN was implemented without a frozen semantic definition

Current implementation uses an inclusive axis-aligned bounding rectangle.

R1 freezes the generic definition:

For absolute squares A and B, let `(df, dr) = B-A` and
`g = gcd(abs(df), abs(dr))`.
- If `g <= 1`, `PATH_BETWEEN(A,B)` is empty.
- Otherwise use primitive step `(df/g, dr/g)`.
- The selected squares are exactly
  `A + k * step`, `k = 1 .. g-1`.
- Endpoints are excluded.
- It is a discrete lattice segment, not a rectangle.

This definition is game-independent and works for orthogonal, diagonal and
other primitive lattice slopes.
