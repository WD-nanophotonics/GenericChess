## B2｜方向、方法论和机会成本（优先独立判断）

项目目标仍是：在若干彼此不同、严格定义的纯 Leaper 游戏上，以可迁移的机制降低搜索成本并提高固定计算时间下的决策/对局表现，然后才扩展一般规则。用户此前已反复提出用 Leaper 的数学结构做规则编译；这是既定方向，不是本轮审查者的新发明。把 p49、p53 的 D3/D4 结果修对，只能作为检测特定视野效应的辅助手段，不能代替跨规则收益。

我的独立优先级判断仍是先做一轮**低开销、可拒绝的热点/语义可行性审计**，而非立刻重构为另一个搜索框架。规则数学编译和搜索树选择是不同轴：前者压低每节点费用，后者减少需要搜索的节点。Stockfish 采用位图攻击与特殊合法性判定（[movegen](https://github.com/official-stockfish/Stockfish/blob/master/src/movegen.cpp)、[position](https://github.com/official-stockfish/Stockfish/blob/master/src/position.cpp)），提供了可参考的实现范式，但其棋种、规则、评价和搜索分布与本项目不同。成熟引擎中的 PVS、LMR、history 等算法只能作为对照路线，不能不经规则与完整终局验证就照搬；本仓库的保守 LMR 原型目前是负结果。

机会成本反事实：继续已曝光 root 的 anchor0 消融，可能得到一项精细特征结论，但当前 [mainline](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/docs/research/LOCAL_MAINLINE.md) 报告此前相关逻辑累计交付成本 116.004747 分钟，追加同一链条约 35 分钟将越过项目既定 ≥120 分钟用户审批界限；且 17 根/9 规则只是训练暴露样本、尚未验证真实 Player 优势。转而只读核对 Native/Runtime 调用与已有 profile 的完整总费用，能先回答“是否存在超过维护成本的可编译热路径”，预计信息收益更直接，但当前无法凭现有数据为加速比和完整工程成本给出可靠数字。**建议维持当前已调整的主线，不恢复 anchor0 大批消费或沿 p49/p53 调参；若审计发现特化开销不占主耗时，则停止这一特定快路径，重新评估动作排序/选择性搜索的跨规则质量试验。**

## A｜工程、代数表达与现有实现

现有 [CompiledRuleSet](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/generic_chess/rules/compiled.py#L51-L81) 已编译 `leap_targets`、`empty_mobility`；[五轨道脚本](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/scripts/leaper_design.py#L26-L36) 已把 `(1,0),(1,1),(2,0),(2,1),(2,2)` 编为整数掩码；[Native legality](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/generic_chess/ai/alphabeta/native_legality.py#L86-L153) 有状态打包、in_check、availability 查询与一次输入复用；[SearchPathRuntime](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/generic_chess/core/search_runtime.py#L512-L576) 已有普通 BoardMove 触及格的 legacy 增量哈希。建议“预先求每个 Leaper 的目标格”或“重做一次 push”会重复既有设施；[现有 Qsearch](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/generic_chess/ai/alphabeta/search.py#L673-L825) 对需要递归的 noisy-child 已在同一次推入的状态里继续递归。

还可量测的执行缺口是 [Core attacks](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/generic_chess/core/attacks.py#L34-L102) 的逐棋子查询、[Evaluator](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/generic_chess/ai/evaluation/evaluator.py#L84-L123) 的攻击集合构造、`_semantic_component_diff_hash` 的全棋盘逐格差分，以及 Native 每次查询的 Python payload/pack 边界。这些源码存在不等于它们在**当前生产搜索**中必然主导耗时。[Native 原始报告](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/docs/research/LEAPER_NATIVE_DEFAULT_20261025.md) 的观察型 profile 将同源调用从 2.138s 扰动为 5.638s，不能把被扰动采样时间直接拆成无扰动成本份额。

可形式化的安全加速是对通过编译期准入的普通纯 Leaper，先生成每种棋子、朝向与格子的攻击位掩码；对王格 `k` 可用反向来源掩码 `R_t(k)` 与对应敌方棋种占据位图 `P_t` 交集判断攻击。普通非王行动若走前己王安全、敌方各子攻击几何只由其类型/位置决定、行动只移动己子并可能删除一个敌子，则敌方对王的攻击集不可能增加，某种重复检查可安全跳过。**准入证明必须排除**射线/阻挡依赖、升变/drop、pass、复合触发、占据相关攻击、额外 auxiliary state 变化；即便入选，也不能绕过终局判定、将军时的合法应对、重复历史/计步时钟、TT精确身份、合法动作顺序与 make/unmake。还有一个具体实现陷阱：多人攻击掩码合并为 OR 后，移走一子不能简单 XOR 掉该子的掩码，重叠攻击格会被错误清除；需维护计数、按类局部重建或使用反向来源查询。

[Knuth, *Leaper Graphs*](https://arxiv.org/abs/math/9411240) 可供编译时分析连通分量、格点模类与距离约束，但原论文的单一 `{r,s}`-Leaper 定理不能不经证明用于五轨道组合，更不能把移动图的分量直接当成整局 WDL 事实。当前尚无这些特化机制的新增实验收益证据。

[Ordinary Q 排序](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/docs/research/LEAPER_ORDINARY_QORDER_20261025.md) 在相同 Native/PVS 控制下的 50k 成本 `517.716→522.642s`，64 根决策相同；24 对局 `23 DRAW / 1 candidate LOSS`，不能声称棋力进步。[保守 LMR](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/docs/research/LEAPER_LMR_QUALITY_20261025.md) 在19根固定输入上无 WDL 修复且 50k 成本上升约 3%；降低访问事件数也不等于总用时降低。最新 [Root/frontier 报告](https://github.com/WD-nanophotonics/GenericChess/blob/45adda191f28913ecafcc4ed66608ef78e9d32e0/docs/research/LEAPER_ROOT_COST_20261025.md) 关闭了 aspiration50 与 p49/p53 root-child 诊断，32 个新 Player 返回、67.317 分钟有效研究时间，未给出新搜索器质量改进。SOURCE_GRAPH 的 WDL 标签、已命名动作证明、有限深度分数、完整 Core 终局和截断 UNKNOWN 仍需分别标记，不可混合成独立新求解。未见来自当前两分支的新增可复现实验，也未在本轮执行任何验证。

## 可证伪的小步与停止门槛

**建议一（现主线的 go/no-go，给 PRIMARY 自主评估）**：冻结至少 3 套棋盘尺寸/轨道差异明显的已存在纯 Leaper 规则和几条完整 GameRecord（正常局面、将军、吃子、临近重复或计步阈值），只读逐项盘点调用路径与 Native 命中率，并在用户许可的现有小额预算内进行少量成对、无扰动的完整查询计时；优先判断每一步完整查询中 Python/Native 打包、Semantic 全板差分、评价攻击图到底哪些被实际调用、能否通过严格准入消除。一次逻辑实验须在实施前封存预估总工作时间和现有相关准备成本，不得借新 session 抹掉已累计的 116 分钟链条。若发现候选热点实际上不在当前路径、或者占比不足以偿付复杂度，则停止快路径实现，不为“数学上整洁”造第二套 Core。

**建议二（仅在一成立后）**：做一个不改变 AlphaBeta/PVS/Q/TT/动态评价、只替换经过证明的纯 Leaper执行路径的可逆最小原型；对同样的完整历史逐项比较合法行动及顺序约束、走棋/撤销、王安全、Core terminal/repetition/clock、TT键、同深度动作/分数/PV、总 wall/CPU/启动和打包开销、nodes/qnodes及删失。任何语义/历史差异立即停止；若只有微基准变快而整次查询无稳定收益亦停止。只有整体查询节约确认后，才预登记固定时间/交换先后手、涵盖不同且未用于设计调参的 Leaper规则的实际对局；不要用 NPS 或单个 p49/p53 的事后标签认定棋力提升。
