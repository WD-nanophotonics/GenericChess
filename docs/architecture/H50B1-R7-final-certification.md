# H50B1-R7 isolated regression and binary provenance closure

R7 is record-only and keeps the R5 Native production implementation frozen.
The executable audit is `scripts/audit_h50b1_r7_final.py`; regression evidence
is generated by `scripts/run_r7_regression.py` and summarized in
`tests/fixtures/h50b1_r7_final_certification.json`.

The H50A record is from a fresh worktree at `7ff0039...`: the loaded module is
inside that worktree, its Native capability reports semantic payload version 2,
and its complete pytest result is parsed from JUnit/raw artifacts.  The current
R7 record similarly probes the freshly built version-4 Native module and parses
the current complete production pytest result.  The R7 certification test file
is explicitly excluded from that run to prevent self-referential evidence; it
is run separately in the focused certification gate.  Historical repair rows and their count are
derived from the parsed H50A failure set; the two residual identifiers are only
an allowlist for failures actually present in the result.

R7 also replays the accepted R6 semantic differential, declaration/spatial
controls, generic payload witness, ABI measurements, F49 scientific-contract
equality, and cumulative production scope.  `generic_chess/` is unchanged from
R6 and R5.  F50B2 remains `NOT_STARTED`; promotion remains `HOLD` pending
independent review.

The user's resource policy is carried forward to the next boundary: retain one
Worker, one repository writer, and one top-level Heavy job, while allowing
independent partitions to use measured CPU and memory in parallel within those
boundaries.  Use isolated caches/TTs, atomic outputs, and deterministic ordered
merge; re-audit conservative limits such as Below Normal priority, one global
computation subprocess, F49 serial loops, Native single-threading, and tiny TT
before F50B2.  This R7 record does not change production code or those limits.
