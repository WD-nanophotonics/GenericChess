# F63-R1-R5 stage-scoped compute governance

The candidate resume harness now exposes exactly one stage per invocation:
`common-4`, `selected-8`, or `selected-32`. The default aggregate resume path
is not an executable entry point. This makes the compute gate's exact command,
resource envelope, current sandbox SHA, and Chat/Supervisor approvals apply to
one cost boundary at a time.

`common-4` validates the frozen teacher decision, F62 reusable evidence, and
all three candidate identities before running the three equal four-pair
comparisons. `selected-8` requires a complete common stage and selects the
candidate by the predeclared game-result tie break. `selected-32` requires the
selected-8 continuation decision: PASS_LOCKED or a completed unresolved stage
may continue; FAIL_LOCKED and unresolved operational interruption do not.

Each stage has its own game-v1 progress identity and caps. A pause, hard cap,
or other operational interruption remains resumable/inconclusive. Positive
scientific classification still requires a complete 32-pair result with its
actual pair-level bootstrap lower bound above 0.5.

The aggregate resource plan is intentionally retired. Before any candidate
Heavy, generate three separate current-SHA resource envelopes and plans, one
for each stage, and obtain fresh Chat plus registered-Supervisor approval at
each boundary. Stage 2 is not approved merely because stage 1 was approved;
stage 3 is not approved until stage-2 evidence shows that more precision is
decision-relevant.
