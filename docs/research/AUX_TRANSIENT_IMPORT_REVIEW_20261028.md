## Exact charged boundary

The frozen driver starts its caller clock before capturing the current record
and constructing Player. It also checks the active provider and re-hashes the
private module file before recording constructor_seconds, so that field is
NOT a pure constructor timer. The outer target then includes initial metric
capture, choose_action, decision-to-record conversion and the ended timestamp.
Raw JSON writing, process-memory snapshot/metric-delta bookkeeping and the
subsequent unchanged-session/PV/provider validation are outside that target;
initial input compilation/replay, private build/import, preflight and final
publication are project cost but not that per-call ratio. The absolute caller
deadline starts at the original tick; it is not reset after construction.
Thus4.046% belongs to this specific charged caller, not pure search-loop time
or total engineering/build/project cost. No common overhead is subtracted to
improve the frozen result, and no post-hoc denominator replaces the gate.

## Decision limits

Both timed arms used the new private binary/common adapter; this is not an
old-production versus new-production timing comparison. More than one transport
operation changed, so4.046% is not an isolated SHA-only contribution. Quantized
profile self-CPU or summed inclusive regions cannot supply that decomposition.
Process-total/peak RSS fields are not exclusive candidate allocations or causal
memory savings. The exposed12-root panel is not an independent rule holdout.

The returned data support the producer's frozen NO_GO decision and a narrow
positive observation, with censoring/UNKNOWN preserved. The independent AUX
contribution is full-history/return qualification and local shared-interface
compatibility, not a second implementation or an extension of the closed trial.
Future work requires a genuinely distinct question or new committed endpoint;
none of the missing D8 slots becomes an automatic task.
