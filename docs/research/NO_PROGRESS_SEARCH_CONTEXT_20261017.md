# Complete-history no-progress Core search — 2026-10-17

Science remains OPEN. This segment turns an actual missing Core search capability
into a checked path context: configured no-progress rules keep complete public
history, action-sensitive search keys and terminal precedence, while avoiding a
complete public replay at every DFS child. Native still explicitly declines this
policy. This is a Core capability result, not generic piece-price learning, an
Elo/optimal-WDL claim or an automatic full-Native-search fallback.

The preceding per-child replay prototype remains unadopted. It is superseded by
verified root admission plus reversible progress facts, not by removing the rule,
shortening history or substituting a scalar counter for search identity. The
canonical inventory/reset count law is shared with existing public adjudication;
public immutable replay keeps its existing semantics.

## What is preserved

Every imported record is replayed from a declared initial setup and compared
exactly. Every runtime witness is bound to the corresponding replayed logical
Position; end Position, ply and public repetition counts also match. The imported
terminal is recomputed at the real rule priority. Opaque/incomplete or forged
roots fail closed. The existing complete position/action history remains in
runtime and public search keys, including forced digest/hash collision controls.

The path context stores a quiet count and the first ambiguous progress fact.
Existing Core accepts a genuine entity-creating action before the adjudication
threshold, then raises IncompleteAdjudicationHistoryError at threshold4. An early
counter exception changes legal behavior. The implementation therefore retains
the error through later actions/resets and raises only when the existing
no-progress branch is reached. Earlier repetition/mate/consecutive outcomes retain
their priority. Push, pop and exceptions restore the context together with the
full parent state, counts, history and key.

The implementation does not infer a capture from every semantic board action.
It reuses the original inventory-delta rule, including its explicit ambiguity
boundary, and reads the mover's current type before transition. Promotion, hands,
drops, auxiliary state and complete action signatures are retained.
