## Reproduction

The scripts locate the project root as an ancestor of their own directory:
`check_qsearch_drop_exclusion.py` uses `Path(__file__).resolve().parents[2]`
and the other scripts use `parents[1]`. They therefore only work from a
directory directly under `.local_agent/`, not from this `docs/` location.

To reproduce without rerunning the frozen searches, copy the nine scripts and
the nine result files into a scratch directory one level below `.local_agent/`
in the DEEPSEEK_AUX checkout, for example
`.local_agent/qsearch-drop-exclusion-repro/`, and run there. The analysis and
check scripts read only stored JSON:

```powershell
$root = '<checkout>'
$env:PYTHONPATH = $root
& '<checkout>/.venv/Scripts/python.exe' .local_agent/qsearch-drop-exclusion-repro/analyze_stage1.py
& '<checkout>/.venv/Scripts/python.exe' .local_agent/qsearch-drop-exclusion-repro/analyze_stage2.py
& '<checkout>/.venv/Scripts/python.exe' .local_agent/qsearch-drop-exclusion-repro/check_ties_and_chosen.py
& '<checkout>/.venv/Scripts/python.exe' .local_agent/qsearch-drop-exclusion-repro/replay_check_stage2.py
& '<checkout>/.venv/Scripts/python.exe' .local_agent/qsearch-drop-exclusion-repro/replay_check_extra.py
```

`probe_stage2.py`, `probe_addendum.py` and `bound_profitable_cases.py` do
rerun deterministic searches. Seeds and caps are fixed in the plans; do not
alter them and do not treat a rerun as new evidence against the stored panel.
`replay_check_stage2.py` and `replay_check_extra.py` regenerate the rules and
starts for the named seeds and compare all stored fields; they are the
intended integrity check.
