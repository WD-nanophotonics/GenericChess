# Explicit generated-rule semantic bridge

The opt-in `compile_legacy_ruleset_for_semantic_execution` entry makes validated
square legacy RuleSets runnable through semantic Core, including generated rules,
promotion, hands, drops and replayed history. It preserves the rule fingerprint
and legacy metadata used by the evaluator. Ordinary compilation, default search
routing and the frozen ui-test branch are unchanged. This enables a controlled
backend attribution bridge; it does not establish universal representation parity.

## Supported interface and observed repair

Pass a RuleSet or its ordinary serialized mapping. Legacy validation runs before
the shared normalized IR/completeness and semantic-start validation. Semantic DSL
and rectangular rules use their existing entries. Replay prior moves using the
new representation rather than copying external repetition keys. Typed action
serialization retains pattern/geometry identity; a coordinate action matching
multiple typed choices is ambiguous and rejected. Core support does not remove
Native restrictions or SearchPathRuntime's existing no-progress path-state refusal.

A declared alternate-start session replay exposed a separate Runtime import gap:
only the default start was tried. Runtime now retains that fast path and checks
declared starts against the exact initial history record when it differs, then
replays and verifies every subsequent record and resulting state. Unknown roots,
tampered actions/check facts and conflicting repetition counts remain rejected
or opaque under their existing contracts. Supplied Session witnesses remain the
cheaper normal path. No arbitrary start inference or relaxed history authority.
