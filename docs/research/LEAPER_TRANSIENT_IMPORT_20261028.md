## Question and intervention

Does a separate state-only Native import reduce actual constructor-plus-choose
cost without altering complete search work? Source inspection found ordinary
state packing creates a fresh canonical history SHA even for readonly check and
availability consumers. The candidate skips that SHA and Python empty-auxiliary-
state normalization, while retaining the other payload construction and C state
validation. It does not fuse a search kernel or remove Core history/TT work.

A distinct transient capsule is accepted only by readonly check, availability
and transient legality APIs. Persistent snapshots/keys, terminal/declaration,
material summaries, make/search APIs reject it; supplied history/events are
rejected. Adapter admission is conservative legacy pure-Leaper only; mixed rules,
IR facades and older binaries retain ordinary imports. Existing check-to-
availability reuse is baseline, not a new contribution.
