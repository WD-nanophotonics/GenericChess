## First-reply witness: reject this implementation

A private candidate borrows an already exact parent check and inspects actual
transaction writes against existing capture endpoint dependencies. It retains
the original full transition and every S3/S4 condition. It does not install a
position cache. Eight played states of exposed24-board1994 give identical
first-reply answers, but31/32 counterbalanced micro pairs are slower; the usual
ratios are1.24–1.50. One initial pair is0.75, not a uniform gain. All eight
queries have zero active enemy endpoint rows, so they cannot represent difficult
attack scans or justify a wider-backend benchmark.

The48 actual DSL states/397 candidate transitions agree in exact children;
395 safety fallbacks and zero reused checks in this installed-metadata cohort
qualify fallback behavior, not the borrowed-check fast path. Guard, enemy-retype
and second-invariant countercontrols remain. Reject this implementation without
spending a new whole-search qualification on its negative cost.

## Sparse count: micro gain does not establish caller gain

The original scalar emits a Boolean for every board cell. The candidate reads
every same cell/owner and emits1 only for actual enemies. It changes no material
inventory, q inclusion, transition, terminal/history, callback or ordering.

Across32 state/side cases and both orders, scalar time is0.336–0.584 of original.
Eight1024-node q4 searches on exposed8/24-board roots preserve every non-time
decision/work statistic, full PV and history. Their caller saving ranges
from-1.58% to+0.89%; this is mixed under ordinary concurrent load.

Reachability matters. An initial512-node diagnostic executed two searches, then
failed its expectation that ordinary q classification had run; their decisions
were not saved. Later measured calls find zero count invocations at512, but
both1024 arms perform exactly25,098 calls,14,456,448 board reads and1,154,931
enemy ones. Avoiding13,301,517 zero yields does not avoid those board reads or
physical checked children. A separate16s q4 observation finds61,885 count calls;
q0 has zero. Profiling generator yields is not a clean recoverable wall fraction.

hybrid movement, eight seeded legal prefix plies, identical rule profiles/Core

## Native boundary: codec, storage and stop response are separate

Six actual public pack calls accept source/target255 and reject256/575.
Although internal square refs useuint16, the full frozen u64 action uses
eight-bit source/target fields. The actual unchecked C OR formula maps
(to256,from0) and(to0,from1) to the same value. Existing strict caps prevent
this collision. Raising only the board guard/global array cannot make full
large-board legality/search safe.

The installed dimension API reports53,920-byte position/undo and maxply1,024.
An independent ctypes layout agrees. The existing live-copy fixed part is
2,664 bytes. A hypothetical global576-cell array changes it to5,224, adding
2,560 bytes per copy even for old small boards. This is modeled byte volume,
not measured memory traffic, slowdown or an adopted change.

Dot read fixed071 source in a fresh request thread. Adopt its useful separation:
a scoped opt-in readonly attack/check carrier need not consume packed actions
or full history, but must carry all actual board/aux dependencies and decline
to complete Core when unsupported. The old check-to-availability packed-input
handoff must not accept a new readonly carrier as if it supported the old codec.

The critical objection is stop response. Current C scalar entries hold the GIL
and have no internal checkpoint; wrapper polls before/after do not prove timely
mid-scan cancellation. Releasing the GIL alone does not stop an active scan.
Do not claim this is a measured current user failure or require a new framework;
measure the actual proposed path.

The current check_provider only reaches _gave_check. S3/root/other-owner queries
retain Core. The old partial64s profile has _gave_check4.605 inclusive seconds
versus in_check11.890; nested profiling is not a wall saving or an all-query hook.
Whole-caller import/query costs and actual hook counts must govern selection.

We actually begin the next finite input control:18/24-board synthetic typed
roots with source and anchor above255, identical boards and a persistent aux
square token whose value flips the child's check. Four normal and four
cancelled real Core runtime pushes observe16/22 actual capture bindings and
restore position/history/identity/depth. Cancel is injected inside an active
Core query after a binding exists. These are Core controls with declared empty
root history, not a reachable-game curriculum, asynchronous request/GIL latency,
Native-wide support or new speed evidence. A Native prototype remains future work.

preliminary attributed summaries, not PRIMARY-verified games/labels/binaries.
Dot's advice separates legal-action WDL range, price-selected action range,

distinguishes uncertain categories. Oracle order must not supply fallback/tie
choices, and ambiguous labels must remain unresolved; this source review does
not verify AUX's32 responses or establish generic-rule prices.

Our new finite mathematical diagnostic preserves one shared outcome per action.
For action domains D and selected s, independent-domain regret bounds are
max(0,max other minima - selected maximum) and
max(0,max other maxima - selected minimum). Paired gain is exactly0 when both
prices choose the same action, even if that label is unknown. A single legal
unknown action has regret0; naive independent intervals would invent uncertainty.
22,830 exhaustive domain/choice cases verify these formulas. They are exact for
the stated independent-domain model, conservative with additional game
correlations, not tablebase probabilities or new training. Different winning
choices and cancelling per-root gains remain different phenomena.
