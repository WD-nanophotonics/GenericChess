# Complete-child q classification cost and forward-model alternatives

Two small private classifiers retain complete Core child commits and the same
q inclusion policy. Neither alters production source, defaults or UI. They
investigate repeated full-board enemy/material counts observed in the supported
mixedD4 profile, without a new runtime, cache, Native kernel or footprint guess.

The first combines the child enemy count and inventory scan, adding hands only
after the capture decision. The second keeps an immutable actual parent-position
reference before pushing, scans all parent/child board pairs and updates a copy
of the parent inventory from actual differences and hand changes. It preserves
explicit zero hand-key presence. Legacy/context-absent cases keep the original
predicate. Spatial/auxiliary changes, complete terminal/history and check probes
remain the existing Core operations. These finite controls concern valid typed
Core states; they do not certify arbitrary malformed duck objects.

## Primary literature and an actual-rule counterexample

[Regular Games, arXiv2511.10593v1](https://arxiv.org/html/2511.10593v1)
uses a compiled automaton forward model with explicit move labels and compiler
analysis. Its section4 performance table measures flat Monte Carlo playouts,
with disclosed rule/turn-limit and promotion differences. That benchmark is not
a matched Core q4 or specialist alpha-beta interval. Its representation and
compiler transformations motivate mechanical analysis of existing rules, not
a new translator/framework here. No reported external speed factor is imported.

[Optimised Playout Implementations for Ludii](https://arxiv.org/pdf/2111.02839)
explicitly separates playout shortcuts from tree-building/minimax requirements
and mechanically recognizes restricted applicable rules. Its add-to-empty and
other simulation-specific shortcuts cannot be assumed valid for our capture,
promotion, drop and history-dependent domain. This supports conditional capability
selection instead of removing mechanisms to claim a generic result.

[Split Moves for MCTS](https://ludii.games/citations/AAAI2022.pdf)
distinguishes complete-move states from intermediate/dead partial states and
notes that random semimove traversal can induce a nonuniform full-move distribution.
It studies MCTS; no local alpha-beta speed evidence follows. A hypothetical
partial-turn adapter must preserve complete-turn depth and terminal/history
boundaries before an equal-resource decision comparison.

Our zero-search exact calculation uses actual full Core legal actions at the
same three generated prefix states. Hypothetically choosing a board source or
drop type uniformly, then a complete legal action within that group uniformly,
is different from the current flat complete-action sampler:

For a group of size n_g among K groups, each action receives1/(K*n_g), while
flat sampling assigns1/N. Equality requires every group size to equalN/K.
A minimal three-action example A/B1/B2 gives1/3 each under flat sampling versus
1/2,1/4,1/4 after uniform group selection. If only A has terminal reward1,
expected feedback changes from1/3 to1/2 although the complete game is unchanged.
This is our explicit mathematical counterexample, not an observed bug, current
sampler change, training run or claim about human prices. Actual complete action
identities, promotion/drop options and full roots are retained in the archive.

This matters if a future execution/sampling interface is reorganized: faster
partial-action traversal may alter a statistical value objective or effective
search horizon. Keep current sampling untouched. Next measure a concrete existing
consumer operation or declare a changed representation premise and a finite
counterexample/control; do not claim gains from unmatched external benchmarks.
