# A capture-safe reference cannot retain the same capture-conditioned deployment

The audit was frozen in `SAFE_REFERENCE_SUPPORT_PROTOCOL.md`. It reads only
the existing unlabelled corpus; the deployment actor-task labels remain unread.
Twelve public selected-capture replays exactly reproduce full saved child
evidence, ongoing status and ordinary own-board count delta -e_t. All twelve
parents therefore violate the proposed no-opponent-ordinary-capture predicate.
Replays and compilation cost 0.188 s; certificate:
`data/safe_reference_support_20261004.json`. This is a compatibility observation,
not a new reference sample, score or estimate of safe-context frequency.

Let S mean no legal owner-one capture of an ordinary owner-zero token in the
reset parent; let C_t mean at least one such type-t capture with an ongoing
child. By definition C_t is a subset of complement S. For any probability law
Q and any t, Q(S intersect C_t)=0. If Q(S)>0, the safety-conditioned law
Q_S(C_t)=0; if Q(S)=0, Q_S itself is undefined. Thus deployment sampling from
Q_S conditioned on C_t is undefined in either case. More attempts cannot fix
the empty intersection, and dropping victim strata would not fix the contract.
The finite witness replays check that the implementation's actual capture
operator is the event used in that algebra, rather than a pseudo-threat mask.

This does NOT prohibit a safe reference and separately declared deployment
from the original Q. That would be a new cross-population transfer hypothesis,
with new independently justified semantics and validation. It cannot be sold
as unchanged same-Q conditioning or repaired by ordinary importance weights:
the safe reference gives zero mass to the required capture-parent support.
The existing twelve unlabelled children are not automatically repurposed or
read to select a replacement formula. No new sampler or population is adopted.
