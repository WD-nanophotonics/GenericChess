# Discarded material ordering view

The production change is limited to explicitly uncached, static material
ordering. It reuses the generic effects/postcondition executor and full parent
history. The temporary child is scored immediately and discarded; it never
enters search, TT, cache, terminal adjudication or a public PV. Cached, dynamic,
spatial, localized, compact-order and policy-order consumers retain full child
identity. A compact leaf evaluator can coexist with static ordering.

Required nested reply computations still construct canonical identity and
propagate internal errors. The omitted top-level child digest is unused by this
consumer; deleting that computation deliberately removes its allocation/failure
opportunity. This is valid-input semantic equivalence with explicit necessary
failure handling, not identical OOM trajectories. The existing capacity refusal
is retained. Default cache=True, q policy, UI and learned models are unchanged.

The actual counter ordering_material_view_trials reports attempts on this path,
not accepted unique states. The Python result exposes None for an older kernel
or a search that did not start; zero is an observed count, not a fallback claim.
