# Complete q frontier ordering and the price boundary

Science is OPEN. This segment asks whether changing the order of a complete
generic q frontier can avoid expensive checked-child work. It follows the
fact-reuse change at d7fd6bec545b16d61123c87462291114ef9faa63. This is search
work/decision attribution, not an Elo campaign or a fitted piece-price result.

## Methods and measured work

All generated candidates remain in the frontier. Normal full checked execution
and the existing actual enemy removal/inventory/check/terminal predicate decide
legality and q inclusion; promotion/drop/auxiliary/history semantics are retained.
A parent-only target-occupancy hint cannot classify all generic captures or
promotions. It only permutes candidates; it never filters them or substitutes
for complete child execution. Quiet inventory-preserving drops remain governed
by the existing full predicate. Checked nodes still consider all evasions.

The first private hint puts direct target-enemy candidates first, ordered by a
coarse victim/actor material hint, then positive promotion-field gain, then
canonical action code. A second private method uses only binary target-enemy
priority and canonical ties. It never reads leaf/hand prices. The latter tests
whether work savings require coupling a price comparison to move ordering.
No new human labels, exposed-price fitting or state/history projection.

Both private arms carry the same four per-context counters: q candidate codes
emitted, outer q full-checked attempts, successful checked children and selected
noisy recursive edges. They do not count nested terminal-availability work,
all physical transitions or unique states. Resource counters include unfinished
next iterations; retained depth/q metadata describe the delivered result.
Matched fixed depth is a common objective, not a claim of the same tree.
Allocation, sorting and extra clock checkpoints are included in measured cost;
wall cancellation schedules need not match after the order changes.
